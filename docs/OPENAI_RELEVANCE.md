## 2. Claims the prototype supports (synthetic or simulation only)

### Episode classification
- **Failed tasks are not treated as bad data**, on the synthetic corpus. 16/16 clean failed tasks were kept as
  `valid_failed_task`, and 40/40 clean episodes preserved [DET].
- **The rules detect injected defects of the declared types.** Each of 15 detectable defect types was caught 4/4;
  per-rule precision was 1.000 with 0 false positives [DET]. Label flips without state evidence were caught 0/4,
  which is undetectable by design [DET].

### Synthetic operations package
- **Ops events are linked to episodes and change their classification.** 43 episodes with linked
  `CAM_FRAME_DROP` recording-failure events were classed `infrastructure_error`, not `invalid_data` [PIL], matching
  planted pattern P1 [TRUTH].
- **Yield loss is attributed once per episode** [RECOMP]. Of 51 lost episodes:

  | Attributed to | Episodes | Episode-hours | Where |
  |---|---|---|---|
  | `event data_recording_failure:CAM_FRAME_DROP` | 43 | 0.4408 | 6 sessions, wc-B |
  | `finding C005_missing_outcome` | 8 | 0.0633 | 1 session, wc-C |

- **Rejected and pending-review episodes are kept apart.** `B001_high_rejected_share` counts 43 rejected (invalid +
  recording error) and 8 suspicious pending review [RECOMP].
- **Recurring faults are grouped across sessions:**
  - `CAM_FRAME_DROP`: 43 occurrences across 6 sessions [PIL].
  - `GRIPPER_OVERCURRENT`: 8 occurrences across 4 sessions [PIL].
  - Repeat failure after resolution: 1/1 [PIL], matching P2 [TRUTH].
- **Missing data is reported as missing.** wc-C availability is "not computable" rather than 100% [PIL], matching P3.
  Strict verified yield is reported as 0/480 rather than inferred [PILj].
- **Usable-data yield is computed with a stated definition:** 89.4% (429/480, 95% CI [86.3, 91.8]), rule `yield/1.0`
  [PIL].
- **All 6 planted patterns surfaced**, including 8 duplicate events dropped [PILj, TRUTH].
- **The source was not modified** (`source_unchanged: true`, 480 episodes processed in 5.579 s) [PILj].

### Simulation experiment [SIM]
- Exact reproduction of 40/40 failures, in both rerun and action replay.
- Held-out results:

  | Baseline | 862 | — | — | — |

- Regression suite: 61/101 cases pass for the baseline and 84/101 for the selected arm, with 0 regressed.

## 3. Claims that need external validation

- **Precision and recall on real collection data.** The synthetic corpora and the rules came from the same author,
  and two declarations were corrected after the first evaluation run (`amperes/sim/runner.py`, `amperes/quality.py`
  `C004_truncated` comments).
- **Whether yield-loss attribution matches a real team's own root-cause analysis.** It is record linkage and prefers
  a linked event over a finding.
- **Workflow time saved. Not measured.** The `workflow_tasks` table in `amperes_data/amperes.db` is empty.
- **Reviewer-confirmed precision. None yet.** 0 of 56 non-info findings reviewed; 397 info notes excluded [RECOMP].
- **Whether the validity classes and yield definition match how a real team decides usability.**
- **Whether planted-pattern detection generalizes** to real fault mixes, and whether the bottleneck associations
  help real root-cause analysis.
- **Any value of a yield change.** The economic model treats the yield gain as an assumption
  ([ECONOMIC_VALUE_MODEL.md](ECONOMIC_VALUE_MODEL.md)).
- **Sim-to-real.** No simulator result says anything about physical robots or learned policies.
- **Throughput and scale** beyond one synthetic package of 480 episodes.

## 4. Claims that need customer-specific integration

- **An importer for the customer's format.** Only `jsonl` and `csv_package` adapters exist (`amperes/ingest/`).
- **Stream declarations** (rates, valid ranges, staleness limits). Rules check only what is declared.
- **Event mapping** to `amperes/ops.py` `EVENT_TYPES`, with consistent episode, session and workcell IDs. Attribution
  depends on events carrying episode IDs.
- **Customer-agreed values** for `rules.json` and `analysis.json`. The mechanism now exists; the values must be
  agreed per customer.
- **Independent outcome evidence** (declared criteria or state), so successes can become `verified_success`.
- **Ticketing integration.** Incidents currently export only as JSON or Markdown.
- **Multi-site aggregation.**
- **Security review, and deployment inside the customer's environment.**
