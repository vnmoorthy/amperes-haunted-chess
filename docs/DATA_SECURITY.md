# Data security and handling

This describes the behaviour of the code in this repository as of 2026-10-29. It is not a compliance certification:
Amperes has **no** SOC 2, ISO 27001 or similar attestation, and no third-party security review.

## Default data flow (local-first)

1. Source files are opened **read-only**. Import and shadow mode compute a SHA-256 fingerprint of every source file
   before and after processing and report `source_unchanged`. Shadow mode exits non-zero if any file changed.
2. Normalised copies and derived records are written only under `$AMPERES_HOME` (default `./amperes_data`):
   - `amperes.db` holds the index, findings, incidents, events, reviews and study timings;
   - `artifacts/datasets/<dataset_id>/` holds normalised episodes;
   - `artifacts/reports/` holds exports.
3. No network calls are made by the core workflow. There are no background uploads and no telemetry. The UI loads no
   external scripts or fonts. Two **opt-in integrations** do use the network, and only when you run them:
   - **Viam live capture** (`viam record`, Live robot tab) connects to the machine in `.env` and makes read calls only.
     Telemetry is stored locally like any import.
   - **MongoDB Atlas sync** (`atlas sync`) sends episode index rows, findings, incidents, operational events and signature
     vectors to the cluster in `MONGODB_URI`. It never sends raw stream values, credentials or environment variables.
     Once data is in your Atlas cluster, its retention and access are governed by Atlas, not by `delete-dataset`.
   - **MongoDB MCP server for Claude Code** (`.mcp.json` → `scripts/mongodb_mcp.sh`): MongoDB's official server, pinned
     at 3.0.5, in `--readOnly` mode, so no create, update or delete tools are registered. Telemetry is disabled. The
     connection string is read from `.env` at launch and never written to `.mcp.json`. It lets Claude query the cluster
     read-only. Remove the `mongodb` entry from `.mcp.json` to disable it.
4. The API binds to `127.0.0.1` by default. `serve` refuses a non-local host unless `--allow-remote` is passed. There is
   **no authentication**, so do not expose it on a shared network.

## Model providers

- No language model is used in the core workflow, and no provider ships with Amperes.
- `amperes/diagnostics.py` defines an optional provider hook. It activates only if a provider is registered in code **and**
  both `AMPERES_DIAGNOSTIC_PROVIDER=<name>` and `AMPERES_ALLOW_EXTERNAL_MODEL=1` are set. It would send incident facts
  (counts and categories), not raw streams.
- `GET /api/health` reports the diagnostic-model status and data flow. Model output would be stored as an unverified
  hypothesis. Amperes never trains or fine-tunes on customer data.

## Secrets and personal data

- Provenance records list package versions, the platform and a code digest. They never record environment variables.
  The Viam credentials in `.env` are read only by `test_connection.py` and are git-ignored.
- `operator_id` and reviewer ids are expected to be pseudonymous. `review add` rejects reviewer ids that contain `@`.
  Amperes does not try to detect personal data inside free-text fields.

## Access control

- Access control is whatever the host OS provides: filesystem permissions on `$AMPERES_HOME`. There are no user accounts
  or roles, and no encryption at rest beyond the disk's own.

## Deletion

```bash
.venv/bin/python -m amperes.cli delete-dataset <dataset_id> --yes
```

This removes the dataset row and its episodes, quality findings, incidents (including members and history), operational
events, reviews of its findings and incidents, workflow-study tasks drawn from it, its artifact directory, its pilot report
directory and its incident export files. It is verified by `tests/test_data.py::test_dataset_deletion` and
`test_deletion_removes_reports_and_study_rows`. It does **not** remove copies you made elsewhere, or SQLite free pages
(run `sqlite3 amperes_data/amperes.db VACUUM` to compact). To remove everything, delete `$AMPERES_HOME`.

## Sample data

Every sample dataset is generated by `amperes/fixtures.py` and labelled `SYNTHETIC` in its records, in the dataset note,
in the UI banner and in every report. No customer records are included in or mixed into the samples.

## Current limitations

- No authentication or authorization on the API.
- No audit log of who viewed data; the incident history records only status changes.
- SQLite on local disk is suitable for a single analyst workstation pilot, not for multi-user deployment.
